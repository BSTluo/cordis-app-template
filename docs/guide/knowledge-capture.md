# 知识沉淀与文档维护

本文规定项目经验、设计说明和对外文档的存放位置、维护方式与验证标记。它是本仓库知识沉淀流程的权威说明；仓库根目录的 `AGENTS.md` 保留架构和运行约束，并链接到本页。

## 文档目录职责

| 内容 | 存放位置 | 维护方式 |
|---|---|---|
| 面向应用使用者、插件作者的正式指南和参考 | `docs/` | 直接维护 Markdown，并纳入 VitePress 导航 |
| 设计案、实施计划、讨论草稿 | `docs/plans/` | 按需维护，不放入 README 的正式文档索引 |
| 插件对外提供的 Service 使用说明 | `external/<plugin>/docs/` | 以插件文档为唯一权威来源，入口为 `docs/index.md` |
| 汇集后的 Service 文档 | `docs/services/` | 由 `yarn docs` / `yarn docs:build` 预处理生成；禁止手工编辑 |

Service 文档应随插件一同维护，描述服务契约、依赖注入方式、配置、使用示例、错误和生命周期行为，以及适用的插件版本。跨插件运行时交互必须通过 Cordis Service 注册、依赖注入和契约实现，不应通过直接导入其他插件实现来建立依赖。

## 编写正式文档

- 每篇文档使用明确的一级标题，并用二、三级标题组织内容。
- 从读者目标和前置条件开始，给出可执行步骤；代码示例应与文中描述及当前项目配置相符。
- 将事实、建议和未验证假设区分清楚；对易变 API 标明版本范围或核对来源。
- 为新增正式文档添加 VitePress 侧边栏入口，并在[文档首页](../index.md)的相关导航区域保持可发现。
- 使用相对 Markdown 链接连接同目录文档；链接应指向源文档，不要链接生成产物或临时文件。
- `README.md` 只索引面向使用者的正式文档，不索引 `docs/plans/` 中的计划、设计案或草稿。

## Service 文档生成与验证

插件作者应在 `external/<plugin>/docs/index.md` 维护入口，并将文档提交在对应插件目录中。运行 `yarn docs` 或 `yarn docs:build` 时，预处理脚本从插件文档生成 `docs/services/` 下的站点内容及侧边栏数据。需要更新时，修改插件内源文档后重新运行相应命令；不要编辑生成文件。

新增或变更 Service 契约时，应同时核对插件的 `inject`、服务注册名称和 `package.json` 中的 `cordis.service` 元数据，并按[Service 元数据规范](../cordis-service-package-metadata.md)维护依赖声明。

## 验证状态

对涉及运行时行为、API 或版本结论的文档，可在相关段落注明证据和验证状态：

- **已验证**：说明验证所针对的版本或项目基线，以及采用的验证方式。
- **待验证**：明确列出尚未确认的部分，避免读者将示例视为已验证结论。
- **不适用**：仅用于明确说明为何没有运行验证，例如纯概念说明。

状态应随代码、依赖或运行环境变化及时更新；不要留下无法追溯版本的“已验证”结论。纯文字调整无需添加验证徽标。
